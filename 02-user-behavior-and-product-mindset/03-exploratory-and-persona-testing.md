# 03. Исследовательское тестирование и эвристики (Exploratory Testing)

> **Что это такое**: Исследовательское тестирование — это одновременное изучение продукта, проектирование тестов и их немедленное выполнение. Это не «хаотичный клик-тест» (Ad-hoc), а строгая дисциплина, основанная на эвристиках, ментальных моделях и фокусированных сессиях.

---

## 1. Исследовательское тестирование vs Скриптовое

```
Скриптовое тестирование:
[ Написать тест-кейсы ] ──────► [ Прогнать тест-кейсы ] ──────► [ Поставить галочки ]
      (Шаг 1, Шаг 2...)               (Строго по шагам)               (Отчет)

Исследовательское тестирование:
    ┌────────────────────────────────────────────────────────┐
    │                                                        │
    ▼                                                        │
[ Изучение поведения ] ──► [ Формулирование гипотезы ] ──► [ Проверка тестом ]
```

| Параметр | Скриптовое тестирование (Scripted) | Исследовательское тестирование (Exploratory) |
| :--- | :--- | :--- |
| **Фокус** | Подтверждение соответствия документации | Поиск неизвестных рисков, скрытых дефектов и уязвимостей |
| **Свобода тестировщика** | Минимальная (шаг влево — шаг вправо запрещен) | Высокая (тестировщик сам решает, куда углубиться) |
| **Когда применять** | Регрессионный прогон перед релизом, аудит | Новые фичи, сложная бизнес-логика, неполные требования |

## 2. Мнемоника SFDIPOT (San Francisco Depot)

Созданная Джеймсом Бахом (James Bach) мнемоника позволяет мгновенно декомпозировать любую фичу на составляющие, чтобы ничего не упустить:

| Буква | Измерение | Вопросы для проверки |
| :---: | :--- | :--- |
| **S** | **Structure** (Структура) | Из каких физических файлов, библиотек, кода состоит продукт? Что изменилось в сборке? |
| **F** | **Function** (Функции) | Что продукт делает? Какие действия выполняет пользователь (логин, расчет, экспорт)? |
| **D** | **Data** (Данные) | С какими данными работает система? Форматы (JSON, CSV), граничные значения, спецсимволы, пустые списки. |
| **I** | **Interfaces** (Интерфейсы) | Через какие интерфейсы идет взаимодействие? UI, REST API, CLI, очереди сообщений (Kafka/RabbitMQ). |
| **P** | **Platform** (Платформы) | На чем запускается система? ОС (Windows, macOS, Linux, Android, iOS), версии браузеров, аппаратная часть. |
| **O** | **Operations** (Операции) | Кто пользователи и как они это используют? Роли (Админ, Гость), типичные цепочки действий, частота использования. |
| **T** | **Time** (Время) | Как фактор времени влияет на систему? Таймауты, часовые пояса, високосные годы, одновременные действия (concurrency). |

## 3. Туры тестирования (Testing Tours) Джеймса Уиттакера

Представьте, что вы турист, приехавший исследовать незнакомый мегаполис. Туры задают направляющий вектор для исследовательской сессии:

```
                          ТУРЫ ТЕСТИРОВАНИЯ
 ┌───────────────────────┬───────────────────────┬───────────────────────┐
 │     The Money Tour    │ The Bad Neighborhood  │     The Fedex Tour    │
 │ (Где лежат деньги)    │  (Где чаще ломается)  │  (Слежка за данными)  │
 ├───────────────────────┼───────────────────────┼───────────────────────┤
 │  The Landmark Tour    │ The Intellectual Tour │    The Chaos Tour     │
 │  (Главные пути)       │   (Сложные расчеты)   │ (Стресс и разрушение) │
 └───────────────────────┴───────────────────────┴───────────────────────┘
```

1. **The Money Tour (Денежный тур)**:
   - Проверка ключевых сценариев, приносящих бизнесу деньги: корзина, платежный шлюз, продление подписки, показ платной рекламы. Падение здесь = прямые финансовые потери.
2. **The Bad Neighborhood Tour (Тур по неблагополучным районам)**:
   - Исследование модулей, где исторически находили больше всего багов (легаси-код, модуль со сложными тарифами, экран, который доделывали в ночь перед дедлайном).
3. **The Fedex Tour (Тур экспресс-доставки)**:
   - Отслеживание пути порции данных через всю систему: создали заказ в UI ➔ проверили его в базе данных ➔ проверили событие в шине Kafka ➔ проверили отображение в CRM у оператора ➔ проверили email-уведомление.
4. **The Landmark Tour (Тур по достопримечательностям)**:
   - Быстрый обход главных экранов и ключевых фич приложения без глубокого погружения.
5. **The Intellectual Tour (Интеллектуальный тур)**:
   - Проверка самых сложных математических расчетов, скидочных правил, налоговых вычетов, фильтров со сложными логическими условиями (AND / OR / NOT).
6. **The Chaos Tour (Тур хаоса)**:
   - Имитация безумного пользователя: закрытие вкладок, обрыв соединения, случайный ввод абракадабры, одновременные клики по несовместимым кнопкам.

## 4. Управление исследовательским тестированием (SBTM)

Чтобы исследовательское тестирование не превратилось в хаос, используется **Session-Based Test Management (SBTM)**:

### 1. Чартер сессии (Charter)
Краткая формулировка цели исследовательской сессии (на 45–90 минут):
> *«Исследовать модуль фильтрации каталога товаров с целью обнаружения зависаний и некорректной пагинации при комбинировании более 4 фильтров одновременно»*

### 2. Таймбоксинг (Timeboxing)
Четкое ограничение по времени: обычно **60 минут** непрерывного фокуса без отвлечений на чаты и почту.

### 3. Отчет по сессии (Session Log)
По итогам сессии тестировщик фиксирует:
- **Found Bugs**: список найденных дефектов с логами и шагами.
- **Notes / Observations**: подозрительные места, где что-то работает странно или медленно.
- **New Opportunities**: новые идеи для тестов, возникшие по ходу исследования.
- **TBS-метрика**: соотношение времени, потраченного на:
  - *T (Test)* — непосредственное выполнение тестов (в идеале > 70%).
  - *B (Bug)* — оформление баг-репортов и сбор логов.
  - *S (Setup)* — подготовка тестового окружения и тестовых данных.
