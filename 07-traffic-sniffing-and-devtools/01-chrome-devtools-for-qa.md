# 🛠️ Chrome DevTools: главное оружие тестировщика веб-приложений

## 1. Вкладка Network (Сеть) — Анатомия запросов

### Ключевые фильтры:
* **Fetch/XHR:** фильтрует только фоновые асинхронные AJAX/REST-запросы (каталог товаров, оформление заказа, корзина). Именно здесь QA проводит 80% времени.
* **Doc:** загрузка основного HTML документа.
* **JS / CSS:** скрипты и стили (проверка кэширования версий).
* **Img / Media:** изображения товаров (поиск тяжелых неоптимизированных картинок по 10 МБ).
* **WS:** WebSocket-соединения в реальном времени.

### Чек-лист проверки сетевого запроса:
1. **Request URL:** корректен ли адрес эндпоинта и query-параметры (`?category=Одежда&page=1`)?
2. **Request Method:** правильный ли HTTP-метод (`GET`, `POST`, `PUT`, `DELETE`)?
3. **Status Code:** соответствует ли код спецификации (200, 201, 400, 401, 404)?
4. **Request Headers:** передан ли токен авторизации `Authorization: Bearer <token>`, верный ли `Content-Type: application/json`?
5. **Payload / Request Body:** корректно ли фронтенд сериализовал введенные пользователем данные? Нет ли дублирования полей?
6. **Response Body:** содержит ли ответ ожидаемую структуру JSON, нет ли утечки приватных данных (паролей, хешей, внутренних ID)?
7. **Timing (Время отклика):** сколько занял **TTFB (Time to First Byte)** — время ожидания ответа бэкенда. Если TTFB > 2 сек — бэкенд тормозит.

## 2. Эмуляция медленной сети и офлайна (Network Throttling)

Реальные пользователи сидят в лифтах, метро и за городом с плохим мобильным интернетом. Проверять сайт только на гигабитном домашнем Wi-Fi — грубейшая ошибка.

### Как включить:
1. Откройте вкладку **Network**.
2. В верхнем тулбаре найдите дропдаун **No throttling** и выберите:
   * **Fast 4G:** стабильный мобильный интернет.
   * **Slow 3G:** высокий пинг (RTT 400мс) и низкая скорость (400 Кбит/с).
   * **Offline:** полное отсутствие интернета.

### Что проверять тестировщику в режиме Slow 3G / Offline:
* **Индикаторы загрузки (Spinners / Skeletons):** видит ли пользователь лоадер во время ожидания товаров, или интерфейс кажется «зависшим»?
* **Блокировка кнопок (Double Click):** если пользователь 3 раза нажал «Купить» на медленном интернете, отправится ли 3 заказа, или кнопка дизейблится?
* **Офлайн-баннер:** понимает ли пользователь, что пропал интернет, или видит бесконечное белое колесо?

## 3. Секретная фича: Local Overrides (Подмена API прямо в браузере)

> *Знаете ли вы, что для тестирования нестандартных ответов бэкенда (например, пустого каталога, ошибки 500 или скидки 99%) **не обязательно устанавливать Charles Proxy**? Chrome DevTools умеет подменять любые ответы сервера «на лету»!*

### Пошаговая инструкция:
1. В DevTools откройте вкладку **Sources** ➡️ вкладка **Overrides** слева (если скрыта, нажмите `>>`).
2. Нажмите **Select folder for overrides** и выберите любую пустую папку на компьютере (например, `C:\overrides`).
3. Браузер запросит разрешение вверху экрана: нажмите **Разрешить (Allow)**.
4. Перейдите во вкладку **Network**, найдите запрос `GET /api/v1/products`.
5. Кликните по нему правой кнопкой мыши ➡️ **Override content**.
6. В открывшемся редакторе измените JSON (например, поставьте товару цену `1 рубль` или сделайте пустой массив `[]`).
7. Нажмите `Ctrl + S` (`Cmd + S`) и обновите страницу в браузере (`F5`).
8. **Вуаля!** Фронтенд получит подмененные вами данные, а рядом с запросом в Network появится фиолетовая точка `•`.

## 4. Вкладка Console (Ошибки и манипуляции с DOM)

* Красные сообщения (`Uncaught TypeError`, `404 Not Found`) — это баги фронтенда, которые должны попадать в баг-репорты.
* Желтые предупреждения (`Warning`) — часто говорят об устаревших API или проблемах с производительностью.
* **Полезные команды консоли:**
  * `clear()` — очистить консоль.
  * `$0` — возвращает HTML-элемент, выделенный сейчас во вкладке Elements.
  * `localStorage.clear()` — мгновенная очистка локального хранилища.
  * `copy(variable)` — скопировать JSON-объект прямо в буфер обмена Windows/Mac.

## 5. Вкладка Application (Cookies, LocalStorage, Сессии)

* **Cookies:**
  * Проверка флагов безопасности: `HttpOnly` (JS не может прочесть куку через `document.cookie` — защита от XSS), `Secure` (передача только по HTTPS), `SameSite` (защита от CSRF).
  * Тест истечения сессии: удаление куки сессии ➡️ обновление страницы ➡️ пользователь должен быть разлогинен.
* **Storage:**
  * Кнопка **Clear site data** — золотая кнопка, когда нужно стереть все кэши, куки, сервис-воркеры и протестировать сайт глазами абсолютно нового посетителя.

## 6. Экспорт HAR-файла для разработчиков

Если баг воспроизводится нестабильно (раз в 10 попыток), приложите к баг-репорту **HAR-файл** (HTTP Archive).
1. Воспроизведите баг с открытой вкладкой **Network**.
2. Нажмите кнопку со стрелкой вниз **«Export HAR...»** в тулбаре Network.
3. Разработчик сможет импортировать этот файл у себя и увидеть всю цепочку сетевых запросов, заголовков и ответов в точности, как было у вас!
