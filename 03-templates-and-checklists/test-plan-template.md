# 📑 Шаблон: Тест-план проекта (Test Plan по стандарту IEEE 829)

> **Тест-план** — это ключевой документ верхнего уровня, описывающий цели, объемы (Scope), стратегию, графики, критерии готовности и риски тестирования для конкретного релиза или проекта.

---

## 1. Введение и цели (Introduction & Objectives)
* **Проект:** QA Sandbox Shop (Интернет-магазин электроники и книг)
* **Версия релиза:** `v1.2.0-MVP`
* **Цель тестирования:** Проверить готовность функционала каталога, фильтрации, корзины, применения промокодов и создания заказов к публичному запуску. Обеспечить высокое качество пользовательского опыта и предотвратить финансовые утечки (ошибки скидок).

---

## 2. Границы тестирования (Test Scope)

### Входит в объем тестирования (In-Scope):
1. **Каталог товаров:** пагинация, отображение карточек, статус «Нет в наличии» при stock = 0, сортировка по цене и рейтингу.
2. **Живой поиск:** поиск по подстроке, корректность дебаунса (500мс).
3. **Корзина:** добавление, изменение количества, удаление, сохранение состояния.
4. **Промокоды:** валидация промокодов `QA2026`, `FREESHIP`, `FIRST10`, расчет скидки и бесплатной доставки.
5. **Оформление заказа:** валидация полей формы, создание записи в БД, списание складского остатка.
6. **API & Интеграции:** 12 REST эндпоинтов, Swagger документация.
7. **Безопасность:** проверка на XSS в полях ввода, экранирование SQL.

### НЕ входит в объем тестирования (Out of Scope):
* Интеграция с реальными банками и эквайрингом (используется мок успешной оплаты).
* Мобильные нативные приложения под iOS / Android (тестируется только Web Responsive).
* Стресс-тестирование свыше 10 000 одновременно активных пользователей.

## 3. Стратегия и виды тестирования (Test Strategy)

| Уровень / Вид | Описание | Инструменты | Ответственный |
| :--- | :--- | :--- | :--- |
| **Функциональное (Functional)** | Проверка позитивных и негативных сценариев по тест-кейсам | Ручное тестирование | QA Engineer |
| **API Тестирование** | Контрактные тесты, статус-коды, схемы ответов | Postman / Newman | QA Automation |
| **UI E2E Автоматизация** | Сквозные автотесты критического пути покупки | Playwright (Chromium) | QA Automation |
| **Кроссбраузерность** | Chrome, Firefox, Safari (Webkit), Мобильные разрешения | Chrome DevTools, Playwright | QA Engineer |
| **Нагрузочное (Load)** | Тестирование стабильности при 50 одновременных сессиях | k6 | Performance QA |
| **Надежность (Chaos)** | Поведение при задержках 1500мс и падениях бэкенда 500 | Встроенная QA-панель | QA Engineer |

## 4. Критерии начала и окончания (Entry & Exit Criteria)

### Критерии начала тестирования (Entry Criteria):
* [x] Билд успешно собран и развернут в тестовом стенде Docker.
* [x] Smoke-тесты API успешно проходят (100% зелёные).
* [x] База данных PostgreSQL инициализирована и засеяна тестовыми данными (Seeding).
* [x] Доступна актуальная документация Swagger (`/api-docs`).

### Критерии окончания тестирования (Exit Criteria / Ready for Production):
* [x] Выполнено 100% запланированных критических тест-кейсов.
* [x] Нет открытых дефектов уровня **Blocker** и **Critical**.
* [x] Количество открытых дефектов уровня **Major** <= 2 (согласованы с Product Owner).
* [x] Все автотесты Playwright и Newman в GitHub Actions успешно зеленые.
* [x] Подписан и согласован итоговый отчет (Test Summary Report).

## 5. Оценка рисков и план смягчения (Risk Assessment)

| Риск | Вероятность | Влияние | План действий (Mitigation) |
| :--- | :---: | :---: | :--- |
| **Ошибки в расчете скидок промокода** (финансовые потери) | Высокая | Высокое | Создать таблицу решений (Decision Table) с покрытием всех комбинаций корзины. |
| **Фронтенд-зависания при падении бэкенда** | Средняя | Высокое | Провести хаос-тестирование с симуляцией HTTP 500 и таймаутов, проверить наличие Error Banners. |
| **Flaky-падения автотестов в CI** | Средняя | Среднее | Настроить авторетраи (retries: 2) и встроенные ожидания селекторов Playwright. |

---

## 6. График и контрольные точки (Schedule)

* **День 1:** Анализ требований, декомпозиция, подготовка тест-дизайна и тест-кейсов.
* **День 2:** Развертывание тестового стенда, Smoke и функциональное тестирование каталога и корзины.
* **День 3:** Тестирование API через Postman, проверка крайних условий промокодов.
* **День 4:** Запуск и стабилизация Playwright E2E автотестов в CI/CD.
* **День 5:** Регрессионное тестирование, составление Test Summary Report, релизный митинг.
