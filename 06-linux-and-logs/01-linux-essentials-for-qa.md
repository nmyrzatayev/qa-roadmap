## 1. Навигация и работа с файлами

| Команда | Описание | Пример |
| :--- | :--- | :--- |
| `pwd` | Вывести текущую директорию (Print Working Directory) | `pwd` |
| `ls -la` | Список всех файлов и папок (включая скрытые) с правами и размером | `ls -la /var/log` |
| `cd <path>` | Переход в директорию (`cd ..` — на уровень выше, `cd ~` — в домашнюю) | `cd /var/log/nginx` |
| `mkdir -p <dir>` | Создать папку (флаг `-p` создает всю цепочку подпапок) | `mkdir -p ./test-artifacts/logs` |
| `cp -r <src> <dest>`| Скопировать файл или папку (`-r` рекурсивно) | `cp config.env.sample config.env` |
| `mv <src> <dest>`| Переместить или переименовать файл | `mv old_report.json new_report.json` |
| `rm -rf <path>` | ⚠️ Удалить файл или директорию принудительно | `rm -rf ./tmp/cache` |
| `find <dir> -name "<pattern>"` | Найти файлы по имени или маске | `find . -name "*.log" -mtime -1` |

## 2. Чтение и просмотр логов

*Никогда не открывайте 500-мегабайтные логи через `cat` или текстовый редактор `nano/vim` — сервер зависнет!*

### `tail` — просмотр конца файла (самый частый инструмент QA)
```bash
# Посмотреть последние 100 строк лога
tail -n 100 app.log

# Режим реального времени (следовать за логом при выполнении действий в браузере):
tail -f app.log

# Следовать за логом с выводом последних 50 строк:
tail -50f /var/log/nginx/error.log
```

### `head` — просмотр начала файла
```bash
# Посмотреть первые 20 строк файла (например, заголовок CSV или конфигурации)
head -n 20 data.csv
```

### `less` — удобная постраничная навигация по огромным файлам
```bash
less production.log
```
* **Горячие клавиши в `less`:**
  * `Shift + G` — перейти в самый конец файла.
  * `g` — перейти в самое начало файла.
  * `/Error` — поиск слова `Error` вниз по файлу (`n` — следующее совпадение, `N` — предыдущее).
  * `?Exception` — поиск слова назад вверх по файлу.
  * `q` — выйти из режима просмотра.

## 3. Фильтрация и поиск (Grep, Awk, Sed, Sort, Uniq)

Магия Linux заключается в пайплайнах (символ `|` — конвейер), когда вывод одной команды передается на вход другой.

### `grep` — поиск по шаблону
```bash
# Найти все строки с ошибками (без учета регистра)
grep -i "error" app.log

# Найти ошибки и показать 3 строки ДО и 3 строки ПОСЛЕ совпадения (контекст стектрейса):
grep -i -C 3 "NullPointerException" app.log

# Найти все строки, где НЕТ слова "DEBUG" (инверсия):
grep -v "DEBUG" app.log

# Посчитать количество ошибок 500 в логе:
grep -c "HTTP/1.1\" 500" access.log
```

### Комбинации: Пайплайн расследования инцидентов

#### 1. Узнать Топ-10 IP-адресов, с которых идет больше всего запросов:
```bash
awk '{print $1}' access.log | sort | uniq -c | sort -nr | head -n 10
```
*Что происходит:* берем 1-ю колонку (IP), сортируем, группируем с подсчетом уникальных (`uniq -c`), сортируем по убыванию (`sort -nr`) и берем первые 10 строк.

#### 2. Посчитать количество разных статус-кодов ответов сервера:
```bash
awk '{print $9}' access.log | sort | uniq -c
# Вывод:
#  14520 200
#    340 304
#     85 404
#     12 500
```

## 4. Процессы, память и ресурсы

| Команда | Что делает | Практическое применение |
| :--- | :--- | :--- |
| `top` / `htop` | Интерактивный монитор загрузки CPU и RAM | Смотрим, не уперся ли бэкенд в 100% процессора во время автотестов |
| `ps aux` | Список всех запущенных процессов | Найти PID зависшего процесса сервиса |
| `ps aux \| grep node` | Найти процесс Node.js | Узнать, запущен ли наш бэкенд |
| `kill -9 <PID>` | Принудительно завершить процесс | Убить зависший процесс |
| `free -h` | Свободная и занятая оперативная память | Проверка на утечки памяти (Memory Leak) |
| `df -h` | Свободное место на жестких дисках | Часто тесты падают из-за того, что диск забился логами (No space left on device) |

## 5. Сеть и клиент-серверные утилиты (Curl, Ping, SS)

### `curl` — ручной швейцарский нож API-тестировщика
```bash
# Простой GET запрос с выводом заголовков ответа (-i):
curl -i http://localhost:5000/health

# POST запрос с отправкой JSON-тела:
curl -X POST http://localhost:5000/api/v1/orders/checkout \
  -H "Content-Type: application/json" \
  -d '{"customer": {"name": "QA Tester", "email": "qa@test.com"}, "items": [{"productId": 1, "quantity": 1}]}'

# Быстро узнать только статус-код ответа:
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:5000/health
```

### Проверка портов и доступности сервисов
```bash
# Проверить, слушает ли порт 5000 или 5432:
ss -tulpn | grep 5000
# или через netstat:
netstat -tuln | grep 5432

# Проверить доступность хоста по сети:
ping -c 4 google.com
```
