# 🐳 Docker для QA Engineer: шпаргалка и управление тестовыми стендами

> В современной разработке все окружения (dev, test, staging) упаковываются в контейнеры Docker. Тестировщику больше не нужно просить сисадмина настроить базу данных или сервер — достаточно запустить одну команду `docker compose up`.

---

## 📌 Главные команды Docker для повседневной работы QA

### 1. Управление контейнерами
```bash
# Посмотреть запущенные контейнеры (имена, порты, статус):
docker ps

# Посмотреть ВСЕ контейнеры (включая остановленные или упавшие с ошибкой):
docker ps -a

# Остановить контейнер по имени или ID:
docker stop qa-shop-backend

# Запустить остановленный контейнер:
docker start qa-shop-backend

# Перезапустить контейнер (после изменения конфига):
docker restart qa-shop-backend
```

---

### 2. Просмотр логов контейнера (Критично для локализации багов!)

Когда при нажатии кнопки в браузере ничего не происходит или выскакивает ошибка 500:

```bash
# Посмотреть последние 100 строк логов бэкенда:
docker logs --tail 100 qa-shop-backend

# Смотреть логи в реальном времени (live streaming):
docker logs -f qa-shop-backend

# Логи с временными метками (timestamp):
docker logs -ft qa-shop-backend

# Найти конкретную ошибку в логах контейнера через grep:
docker logs qa-shop-backend 2>&1 | grep -i "error"
```

---

### 3. Вход внутрь контейнера (Interactive Shell)

Иногда нужно зайти внутрь работающего контейнера, чтобы проверить файлы, сетевую связность или выполнить команду:

```bash
# Войти в терминал контейнера (bash или sh):
docker exec -it qa-shop-backend sh
# или
docker exec -it qa-shop-backend bash

# Выполнить команду внутри контейнера БЕЗ входа в него:
docker exec -it qa-shop-postgres psql -U postgres -d qashop -c "SELECT COUNT(*) FROM products;"
```

---

### 4. Docker Compose (Управление всем стеком проекта)

В нашем проекте `docker-compose.yml` поднимает сразу 3 сервиса: `postgres`, `backend`, `frontend`.

```bash
# 1. Собрать образы и запустить весь стек в фоновом режиме:
docker compose up -d --build

# 2. Проверить статус всех сервисов проекта:
docker compose ps

# 3. Смотреть объединенные логи всех сервисов в реальном времени:
docker compose logs -f

# 4. Смотреть логи только конкретного сервиса:
docker compose logs -f backend

# 5. Остановить все сервисы стека:
docker compose stop

# 6. Полностью остановить и удалить контейнеры:
docker compose down

# 7. Полная очистка с удалением томов данных (сброс базы данных на чистую):
docker compose down -v
```

## 🛠️ Траблшутинг частых проблем в Docker

### Проблема 1: «Port already allocated / Address already in use»
* **Причина:** Порт (например, 5000 или 5432) уже занят локальным сервисом на вашем компьютере или другим проектом.
* **Решение:**
  ```bash
  # Найти процесс, занимающий порт 5000:
  # Windows PowerShell:
  netstat -ano | findstr :5000
  # Linux / macOS:
  lsof -i :5000
  ```
  Либо изменить внешний порт в `docker-compose.yml` (например, `"5001:5000"`).

### Проблема 2: «No space left on device»
* **Причина:** Docker сохраняет старые неиспользуемые слои образов и анонимные тома, забивая свободное место на диске.
* **Решение (Глобальная очистка Docker-мусора):**
  ```bash
  docker system prune -a --volumes -f
  ```
