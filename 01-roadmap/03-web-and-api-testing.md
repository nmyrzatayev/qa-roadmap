## 1. Клиент-серверная архитектура и протокол HTTP

Современные веб-приложения строятся по клиент-серверной модели:
- **Клиент (Frontend)**: Браузер или мобильное приложение (HTML, CSS, JavaScript/TypeScript). Отвечает за отображение и взаимодействие с пользователем.
- **Сервер (Backend)**: Бизнес-логика, обработка данных, авторизация, взаимодействие с базой данных (Node.js, Python, Java, Go, C#).
- **Протокол передачи данных**: HTTP (HyperText Transfer Protocol) / HTTPS (зашифрованный через TLS).

```
 ┌──────────────┐         HTTP Request (GET, POST...)         ┌──────────────┐
 │   Браузер    │ ──────────────────────────────────────────► │    Сервер    │
 │  (Frontend)  │ ◄────────────────────────────────────────── │  (Backend)   │
 └──────────────┘         HTTP Response (Status, JSON...)     └──────┬───────┘
                                                                     │ SQL
                                                                     ▼
                                                              ┌──────────────┐
                                                              │  База Данных │
                                                              └──────────────┘
```

## 2. HTTP Методы и Коды ответов

### Основные HTTP-методы:
- **`GET`**: Получение ресурса (не должен менять состояние сервера; идемпотентный).
- **`POST`**: Создание нового ресурса или отправка формы.
- **`PUT`**: Полная замена существующего ресурса.
- **`PATCH`**: Частичное обновление ресурса (например, изменение только одного поля `status`).
- **`DELETE`**: Удаление ресурса.

> **Понятие идемпотентности**: Метод называется идемпотентным, если повторный вызов с теми же параметрами приводит к тому же состоянию сервера (GET, PUT, DELETE — идемпотентны; POST — обычно нет, так как повторные вызовы создадут несколько записей).

### Коды ответов сервера (Status Codes):

| Диапазон | Категория | Ключевые коды | Значение |
| :--- | :--- | :--- | :--- |
| **`2xx`** | **Успех (Success)** | `200 OK`<br>`201 Created`<br>`204 No Content` | Запрос успешно обработан.<br>Ресурс создан (часто на POST).<br>Успешно, но тела ответа нет (на DELETE). |
| **`3xx`** | **Редиректы (Redirection)**| `301 Moved Permanently`<br>`304 Not Modified` | Постоянный редирект на новый URL.<br>Ресурс взят из кэша. |
| **`4xx`** | **Ошибка клиента (Client Error)** | `400 Bad Request`<br>`401 Unauthorized`<br>`403 Forbidden`<br>`404 Not Found`<br>`409 Conflict`<br>`422 Unprocessable` | Ошибка валидации / некорректный JSON.<br>Пользователь не авторизован (нет токена).<br>Авторизован, но нет прав на этот ресурс.<br>Эндпоинт или сущность не найдены.<br>Конфликт (например, email уже зарегистрирован).<br>Семантическая ошибка данных. |
| **`5xx`** | **Ошибка сервера (Server Error)** | `500 Internal Server Error`<br>`502 Bad Gateway`<br>`503 Service Unavailable`<br>`504 Gateway Timeout` | Необработанное исключение (крэш бэкенда).<br>Прокси/шлюз получил невалидный ответ от апстрима.<br>Сервер перегружен или на техработах.<br>Бэкенд не ответил вовремя прокси-серверу (Nginx). |

## 3. Chrome DevTools для QA: Главные вкладки

Клавиша `F12` (или `Ctrl+Shift+I` / `Cmd+Option+I`) — главный инструмент веб-тестировщика.

### 1. Elements (Элементы)
- Инспекция DOM-дерева и CSS-стилей.
- Поиск багов верстки: наложение элементов, проверка адаптивности (Device Toolbar: иконка смартфона/планшета).
- Проверка состояний элементов: `:hover`, `:focus`, `:active`.

### 2. Console (Консоль)
- Просмотр ошибок JavaScript (`Uncaught TypeError`, синтаксические ошибки).
- Выполнение произвольного JS-кода для отладки.

### 3. Network (Сеть)
- Анализ всех сетевых запросов при действиях на странице.
- **Вкладки запроса**:
  - `Headers`: URL, Method, Status Code, Request/Response Headers.
  - `Payload` (или `Request Body`): какие данные ушли на бэкенд.
  - `Preview` / `Response`: что вернул бэкенд (обычно JSON).
  - `Timing`: сколько времени занял DNS, SSL handshake, TTFB (Time to First Byte) и загрузка контента.
- **Полезные фичи Network**:
  - `Throttling`: имитация медленного интернета (Slow 3G, Offline) для проверки лоадеров и поведения при обрывах.
  - `Preserve log`: сохранение логов при переходе между страницами.
  - `Disable cache`: отключение кэширования для проверки «чистого» состояния.
  - `Save all as HAR with content`: выгрузка полного архива сетевых запросов для прикрепления к баг-репорту.

### 4. Application (Хранилище)
- **Cookies**: проверка cookie авторизации (`token`, `session_id`), флагов безопасности (`HttpOnly`, `Secure`, `SameSite`).
- **LocalStorage & SessionStorage**: проверка сохранения состояния корзины, выбранного языка или темы оформления.
- **Clear site data**: очистка всех кэшей и хранилищ одной кнопкой для воспроизведения сценария «первый визит».

## 4. Тестирование API (REST)

### Что такое REST?
REST (Representational State Transfer) — архитектурный стиль взаимодействия систем, основанный на стандартных методах HTTP и работе с ресурсами через понятные URI:
- `GET /api/v1/users` — список пользователей
- `POST /api/v1/users` — создать пользователя
- `GET /api/v1/users/42` — получить пользователя с ID 42
- `PUT /api/v1/users/42` — обновить данные пользователя с ID 42
- `DELETE /api/v1/users/42` — удалить пользователя с ID 42

### Инструменты:
- **Swagger / OpenAPI**: интерактивная документация, где можно посмотреть схемы запросов/ответов и быстро выполнить тестовый запрос прямо в браузере.
- **Postman**: мощный инструмент тестирования API:
  - Создание коллекций (`Collections`) и окружений (`Environments`: Dev, Staging, Prod).
  - Использование переменных (`{{base_url}}`, `{{token}}`).
  - Автоматические проверки во вкладке `Scripts` / `Tests`:
    ```javascript
    pm.test("Status code is 200", function () {
        pm.response.to.have.status(200);
    });

    pm.test("User object has valid email", function () {
        var jsonData = pm.response.json();
        pm.expect(jsonData.email).to.include("@");
    });
    ```
  - 🎮 **Практический тренажер**: В нашем учебном проекте интернет-магазина реализован эндпоинт [`http://localhost:5000/api/v1/postman`](http://localhost:5000/api/v1/postman), где можно в 1 клик скачать готовую коллекцию со всеми настроенными автотестами для импорта в Postman.

### Чек-лист тестирования API:
1. **Позитивные сценарии**: Валидные параметры, корректные статус-коды (200, 201), правильная структура JSON.
2. **Обязательные и необязательные поля**: Что будет, если не передать обязательное поле? Сервер должен возвращать понятную ошибку `400` / `422`, а не падать с `500`.
3. **Типы данных и граничные значения**: Передача строки вместо числа, `null`, пустой массив `[]`, длинная строка (10 000 знаков).
4. **Аутентификация и авторизация**:
   - Без токена ➔ `401 Unauthorized`.
   - С токеном обычного пользователя обращение к админскому эндпоинту ➔ `403 Forbidden`.
   - Истекший токен (Expired JWT) ➔ `401`.
5. **SQL / NoSQL инъекции и спецсимволы** в параметрах запроса.
6. **Пагинация и лимиты**: Корректно ли работают `?page=1&limit=20`, что будет при отрицательном `page=-1` или `limit=999999`?
