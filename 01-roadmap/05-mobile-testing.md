# 05. Особенности мобильного тестирования

> **Цель модуля**: Разобраться в специфике мобильных платформ (iOS и Android), научиться тестировать мобильные приложения в стрессовых условиях (прерывания, переключение сетей, фоновый режим) и освоить ключевой инструментарий (ADB, Charles / Proxyman).

---

## 1. Специфика мобильного мира: Чем мобилки отличаются от Web?

В мобильном приложении тестировщик сталкивается с факторами, которых почти нет на обычном десктопе:
1. **Фрагментация устройств**:
   - На Android существуют тысячи моделей смартфонов с разными процессорами, оболочками (OneUI, MIUI/HyperOS, Pure Android), плотностью пикселей и вырезами экрана (челки, «островки»).
   - На iOS парк устройств меньше, но присутствуют разные поколения экранов, версии iOS и строгая политика Apple.
2. **Нестабильная среда**:
   - Пользователь едет в метро, заходит в лифт, переключается с домашнего Wi-Fi на 4G.
3. **Ограниченность ресурсов**:
   - Расход батареи, нагрев устройства, нехватка оперативной памяти (ОС может в любой момент выгрузить свернутое приложение).
4. **Управление жестами**:
   - Tap, Double tap, Pinch-to-zoom, Swipe, Long press, жесты «Назад» от края экрана.

## 2. Типы мобильных приложений

| Тип | Технологии | Плюсы | Минусы для QA |
| :--- | :--- | :--- | :--- |
| **Native (Нативные)** | Swift/Obj-C (iOS), Kotlin/Java (Android) | Максимальная скорость, доступ ко всем датчикам и API системы | Нужно тестировать две разные кодовые базы |
| **Cross-Platform** | Flutter, React Native | Единый код для iOS и Android | Специфические баги рендеринга на одной из платформ |
| **PWA / Web-view** | HTML5, CSS, JS внутри обертки браузера | Дешевизна, мгновенные обновления без App Store | Ограниченный доступ к «железу», медленнее отклик |

## 3. Матрица стресс-тестирования мобильных приложений

Опытный QA мобильных приложений всегда тестирует следующие категории кейсов:

### 1. Прерывания (Interruptions)
Что происходит с активным процессом (например, оформлением кредита или заказом такси), если:
- Поступил входящий звонок (GSM или мессенджер)?
- Пришло push-уведомление или сработал будильник?
- Заряд батареи упал до 10% / 20% (появилось системное всплывающее окно)?
- Подключили зарядное устройство или наушники?
- Свернули приложение и открыли камеру?

### 2. Жизненный цикл приложения (App Lifecycle)
- **Foreground (Активное)**: приложение на экране.
- **Background (В фоне)**: приложение свернуто. Не «засыпают» ли фоновые процессы? Не утекает ли память?
- **Suspended / Killed**: ОС «убила» приложение из-за нехватки RAM. При повторном открытии сохранилось ли состояние экрана (черновик сообщения, выбранные фильтры) или всё сбросилось?

### 3. Сетевые метаморфозы
- Переход с **Wi-Fi на мобильный интернет** прямо во время передачи файла или оплаты.
- Включение **Режима полета (Airplane mode)** и последующее выключение.
- Полная потеря сигнала (вход в лифт/туннель) — показывает ли приложение аккуратный экран *«Нет подключения»* с кнопкой *«Повторить»*, или падает с крэшем?
- Медленный интернет (Edge/GPRS) — не дублируются ли запросы при нетерпеливом нажатии кнопки?

### 4. Разрешения (Permissions)
- Запрос разрешения на доступ к геолокации, камере, микрофону, галерее:
  - Что если пользователь нажал «Запретить»? Не падает ли приложение? Показывает ли понятную подсказку, как включить доступ в настройках?
  - Что если пользователь выдал разрешение, но потом отозвал его в настройках ОС во время работы приложения?

### 5. Обновления и совместимость
- Обновление приложения «поверх» старой версии: миграция базы данных (SQLite/Room/CoreData), сохранение пользовательской сессии.
- Поведение при темной/светлой теме оформления (Dark mode).
- Поведение при изменении системного размера шрифта (Accessibility Large Fonts) — не «плывет» ли верстка?

## 4. Необходимые инструменты мобильного QA

### 1. Проксирование сетевого трафика (Charles Proxy / Proxyman)
Позволяет перехватывать весь сетевой трафик смартфона на компьютере:
- Подмена ответов сервера (**Map Local** / **Breakpoints**) — например, подставить ошибку 500 от платежного шлюза без реального сбоя на сервере.
- Замедление скорости интернета (**Throttle**).
- Просмотр точных заголовков и тел запросов/ответов.

### 2. Android Debug Bridge (ADB)
Консольная утилита для работы с Android-устройствами:
```bash
# Список подключенных устройств
adb devices

# Установка APK файла
adb install app-release.apk

# Снятие скриншота со смартфона
adb exec-out screencap -p > screen.png

# Запись видео с экрана
adb shell screenrecord /sdcard/demo.mp4

# Чтение системных логов в реальном времени с фильтром по крэшам
adb logcat *:E

# Имитация входящего звонка или смены заряда батареи через эмулятор
adb emu gsm call +79991234567
```

### 3. Эмуляторы vs Реальные устройства
- **Эмуляторы / Симуляторы** (Android Studio Emulator, Xcode Simulator): отлично подходят для быстрого тестирования верстки, разных разрешений и начальных сборок.
- **Реальные устройства (Real Devices)**: обязательны для финального регресса, тестирования камеры, биометрии (Face ID / Fingerprint), Bluetooth, реального расхода батареи и тактильного отклика.
