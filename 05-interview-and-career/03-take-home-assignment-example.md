# 📋 Пример выполнения реального тестового задания для Junior/Middle QA

> Тестовые задания (Take-home assignments) — обязательный этап отбора на 80% вакансий. Ниже приведен образцовый пример выполнения тестового задания по функционалу нашего интернет-магазина **QA Sandbox Shop**, который вы можете использовать как бенчмарк оформления собственной работы.

---

## 🎯 Исходное задание от работодателя
> **ТЗ:** «Здравствуйте! Протестируйте модуль "Оформление заказа и промокоды" в нашем демо-магазине. 
> 1. Составьте тест-план / чек-лист проверок.
> 2. Оформите 2-3 найденных баг-репорта по стандарту вашей компании.
> 3. Напишите рекомендации по улучшению UX/логики для команды разработки».

---

## 📑 Часть 1. Чек-лист проверок модуля оформления заказа

### 1. Корзина и расчет сумм
- [x] Добавление 1 товара в корзину: бейдж в шапке меняется на `1`, в корзине верный расчет `Количество * Цена`.
- [x] Увеличение/уменьшение количества товара кнопками `+` и `-`.
- [x] Попытка уменьшить товар с количеством 1: кнопка `-` либо неактивна, либо удаляет товар с подтверждением.
- [x] Удаление позиции кнопкой «Корзина» / иконкой мусорки.
- [x] Автоматический пересчет итоговой стоимости при изменении состава корзины.
- [x] Проверка стоимости доставки: при сумме < 3000 ₽ доставка = 350 ₽, при сумме >= 3000 ₽ — бесплатно.

### 2. Применение промокодов
- [x] Позитивный: ввод валидного промокода `QA2026` в верхнем регистре -> скидка 20% применяется, сумма уменьшается.
- [x] Позитивный: ввод промокода `qa2026` в нижнем регистре -> промокод применяется (система делает `.toUpperCase()`).
- [x] Позитивный: промокод с пробелами по краям `"  QA2026  "` -> пробелы обрезаются (trim).
- [x] Негативный: ввод несуществующего промокода `PROMO100` -> сообщение «Недействительный промокод», сумма не меняется.
- [x] Негативный: попытка отправить пустое поле промокода -> поле валидируется, ошибка.
- [x] Граничный случай: удаление товаров из корзины после применения промокода -> сумма скидки корректно пересчитывается от нового subtotal.

### 3. Форма оформления доставки (Checkout Modal)
- [x] Валидация обязательности всех полей (ФИО, Email, Телефон, Адрес).
- [x] Поле Email: позитивные форматы (`test@domain.com`, `user.name+tag@sub.domain.org`), негативные (`plain`, `@nodomain`, `spaces@`).
- [x] Поле Телефон: маска ввода, запрет буквенных символов, минимальная длина (не менее 10 цифр).
- [x] Поле ФИО: проверка на XSS/HTML инъекции (`<script>`, `<b>Тест</b>`).
- [x] Защита от дублирующих кликов (Double Click / Submit spam): при клике на «Подтвердить и оплатить» кнопка переходит в `disabled` со спиннером загрузки.

### 4. Создание заказа и завершение
- [x] Успешная отправка формы: переход на экран «Спасибо за заказ!».
- [x] Генерация уникального номера заказа (формат `ORD-XXXXXXXXXXXX`).
- [x] Очистка корзины после успешного оформления.
- [x] Уменьшение остатка товара (Stock) на складе на купленное количество.

## 🐛 Часть 2. Образцы оформленных баг-репортов

### Баг-репорт 1: Уязвимость хранимой XSS-инъекции в имени покупателя

* **ID:** `BUG-SHOP-01`
* **Заголовок:** XSS-инъекция в поле «ФИО получателя» на странице успешного оформления заказа
* **Серьезность (Severity):** High / Security
* **Приоритет (Priority):** High
* **Компонент:** Frontend / CheckoutModal (`CheckoutModal.jsx`)
* **Окружение:** Google Chrome 124.0, macOS Sonoma 14.4 / Windows 11, Staging стенд (`http://localhost:5173`)

**Шаги для воспроизведения:**
1. Добавить любой товар из каталога в корзину и нажать «Оформить заказ».
2. В поле «ФИО получателя» ввести вредоносный payload: `<img src=x onerror=alert('XSS_ATTACK')>`.
3. Заполнить остальные обязательные поля валидными данными.
4. Нажать кнопку «Подтвердить и оплатить».

**Фактический результат:**
На экране «Спасибо за заказ!» в блоке «Получатель» HTML-код выполняется браузером, всплывает алерт `XSS_ATTACK`. В DOM-дереве строка рендерится через незащищенный `dangerouslySetInnerHTML`.

**Ожидаемый результат:**
Любой пользовательский ввод должен экранироваться (санитизироваться). Текст должен отображаться безопасным plain text без исполнения JS/HTML.

**Скриншот / Видео:** `attachment_xss_screen.png`

### Баг-репорт 2: Регистрозависимость промокода при вводе пользователем

* **ID:** `BUG-SHOP-02`
* **Заголовок:** Промокод `qa2026` в нижнем регистре отклоняется как недействительный
* **Серьезность (Severity):** Minor
* **Приоритет (Priority):** Medium
* **Компонент:** Frontend / CartModal (`CartModal.jsx:27`)

**Шаги для воспроизведения:**
1. Открыть корзину с добавленным товаром.
2. В поле ввода промокода ввести `qa2026` (строчными буквами).
3. Нажать кнопку «Применить».

**Фактический результат:**
Отображается красная ошибка: «Недействительный промокод», скидка 20% не применяется.

**Ожидаемый результат:**
Промокоды для интернет-магазинов должны быть нечувствительны к регистру (Case-insensitive). Фронтенд или бэкенд должны автоматически преобразовывать промокод к `.trim().toUpperCase()`. Покупатель на мобильном телефоне не должен вручную переключать капслок.

## 💡 Часть 3. Рекомендации по улучшению UX и стабильности (Product Mindset)

1. **Обработка двойного клика (Debounce / Loading state):**
   - На медленном мобильном интернете (3G) пользователи склонны нажимать кнопку «Оплатить» несколько раз. Необходимо блокировать кнопку сразу после первого клика и отображать анимированный лоадер, чтобы исключить создание повторных заказов-дубликатов.
2. **Валидация телефона на клиенте:**
   - Сейчас поле телефона принимает любые строковые символы (например, «телефон»). Рекомендуется внедрить маску ввода с валидацией по регулярному выражению еще до нажатия кнопки отправки.
3. **Сохранение введенных данных в LocalStorage при случайном закрытии модалки:**
   - Если пользователь случайно кликнул мимо модального окна (на overlay), форма закрывается и сбрасывает введенный длинный адрес. Рекомендуется сохранять драфт формы или требовать подтверждение при закрытии несохраненной формы.
