# 🛡️ Основы безопасности веб-приложений: OWASP Top-10 для QA Engineer

> Тестирование безопасности (Security Testing) — это поиск уязвимостей, которые злоумышленник может использовать для кражи персональных данных, денег клиентов или вывода сервера из строя. **OWASP (Open Web Application Security Project)** — главный мировой стандарт в области безопасности веб-приложений.

---

## 📌 Главные угрозы OWASP Top-10 простыми словами:

### 1. A01: Broken Access Control (Нарушение контроля доступа / IDOR)
* **В чем суть:** Пользователь с правами обычного покупателя может получить доступ к данным другого пользователя или функциям администратора просто изменив URL или ID в запросе.
* **Пример IDOR (Insecure Direct Object Reference):**
  - Пользователь авторизован как ID 105.
  - При просмотре своего профиля отправляется запрос `GET /api/v1/orders/105`.
  - Тестировщик меняет ID в Postman на `GET /api/v1/orders/106` и видит чужие ФИО, адрес доставки и сумму заказа.
* **Как тестировать:** Попробовать запросить чужие данные под другой сессией, выполнить `DELETE` или `PUT` к чужому ресурсу.

---

### 2. A02: Cryptographic Failures (Сбои криптографии)
* **В чем суть:** Передача паролей или номеров кредитных карт в незашифрованном виде (по HTTP вместо HTTPS), хранение паролей в базе открытым текстом вместо надежных хэшей (`bcrypt`, `argon2`), отсутствие флага `Secure` на авторизационных cookies.
* **Как тестировать:**
  - Проверить, что сайт не позволяет передавать учетные данные по `http://`.
  - Проверить базу данных: пароли должны быть хэшированы (строки вида `$2b$10$...`), а не лежать в виде `123456`.

---

### 3. A03: Injection (Инъекции: SQLi, XSS)
* **SQL Injection (SQLi):**
  - Злоумышленник вводит SQL-конструкции в поле поиска или логина.
  - Пример: ввод `' OR 1=1 --` в форму поиска. Если бэкенд склеивает строки через интерполяцию:
    `SELECT * FROM products WHERE title = '' OR 1=1 --'`, запрос возвращает всю таблицу, игнорируя фильтры.
  - **Защита:** использование параметризованных запросов и ORM (TypeORM, Prisma).
* **Cross-Site Scripting (XSS):**
  - Внедрение исполняемого JavaScript-кода на страницу, который выполнится в браузере других пользователей.
  - **Stored XSS (Хранимый):** вредоносный скрипт сохраняется в БД (например, в отзыве о товаре или имени покупателя) и выполняется каждый раз при открытии страницы.
  - **Угроза:** кража токенов из `LocalStorage`, кража `document.cookie`, перенаправление на фишинговый сайт.

---

### 4. A05: Security Misconfiguration (Небезопасная конфигурация)
* **В чем суть:**
  - Оставленные включенными дефолтные пароли (`admin / admin`).
  - Включенный режим отладки (`DEBUG=true`) в продакшене, из-за чего при ошибке 500 пользователю отдается полный StackTrace с путями к файлам, версиями библиотек и паролями к БД.
  - Лишние открытые служебные порты или публичные эндпоинты swagger (`/api-docs` в боевом проде).

---

### 5. A07: Identification and Authentication Failures (Сбои идентификации)
* **В чем суть:**
  - Отсутствие ограничения попыток ввода пароля (Brute-Force): скрипт может перебирать миллионы паролей в секунду без блокировки IP и без капчи.
  - Разрешение слабых паролей (`123456`, `qwerty`).
  - Утечка информации в сообщениях об ошибках: система говорит *«Пользователь с таким email не найден»*, позволяя злоумышленнику узнать, кто зарегистрирован в системе. Должно быть нейтральное: *«Неверный логин или пароль»*.

---

## 📋 Чек-лист базового Security-тестирования для QA:

1. [ ] Все формы логина и оплаты работают строго по протоколу HTTPS.
2. [ ] В полях ввода проверены спецсимволы `' " < > / \ ; -- /*` и базовые XSS-пейлоады.
3. [ ] Авторизационные куки содержат флаги `HttpOnly` и `Secure`.
4. [ ] Попытка открыть эндпоинт админки без токена возвращает `401 Unauthorized` или `403 Forbidden`.
5. [ ] При ошибках 500 сервер не отдает клиенту чувствительные данные окружения (`.env`, ключи, пароли БД).
6. [ ] После 5 неверных попыток входа появляется временная блокировка или капча.
